Interactive Self-Attention

Transformer Lab

Q と K が「どの語をどれだけ見るか」を決め、 V が「そこから何を持ってくるか」を運ぶ。 I like playing football の4語で、4つの文脈ベクトルができるまでを実際に計算します。

埋め込み→Q, K, V→スコア→softmax→重み付き和

このページについて

Transformer の中心にある self-attention を、4語の文で最後まで手計算できる大きさに縮めた教材です。

self-attention とは

文の中の各語が、同じ文の他のすべての語を見に行き、 自分にとって必要な情報だけを取り込んで自分のベクトルを作り直す仕組みです。 取り込む配分を決めるのが Q と K、 取り込まれる中身が V です。

Attention(Q, K, V) = softmax(Q Kᵀ ⁄ √d_k) V

このページの役割

式の各記号がどの数字なのかを、途中まで丸めずに全部見せます。 語を1つ選ぶと、その語の q が作られ、4つの k と内積を取り、 softmax で配分になり、その配分で v が混ざって z になるまでが1画面に並びます。

本物のモデルとの違い

ここで使う W^Q, W^K, W^V は 学習で得た値ではありません。電卓で追える大きさに収め、 「主語は述語を探す」「動詞は目的語を探す」という関係が現れるように手で書いた値です。 次元も d_model = 4, d_k = 2 と極端に小さく、head も1つだけです。

実際のモデルは d_model が数百〜数千、head が数十あります。 また、q・k・v の各軸に人間が読める意味はありません。 このページも軸に意味を持たせず「軸1」「軸2」と番号でだけ呼びます。

なぜ Q, K, V の3つに分けるのか

3つとも同じ入力から作られます。同じものから3つ作るのは無駄に見えますが、 役割が違います。図書館で本を探す場面に当てはめると分かりやすくなります。

Q

Query — 何を探しているか

自分が文脈から何を補いたいかを表すベクトル。検索窓に打ち込む言葉にあたります。 q_i = x_i W^Q

K

Key — 自分は何として差し出せるか

他の語から見つけてもらうための見出し。本の背表紙にあたります。 q との内積で噛み合いを測るため、k は q と同じ次元 d_k に住みます。 k_j = x_j W^K

V

Value — 実際に渡す中身

見つけてもらったときに相手へ渡す情報。本の中身にあたります。 背表紙と中身が別物でよいのと同じで、k と v は違うベクトルです。 v_j = x_j W^V

ここが最も間違えやすい点です。重みが掛かる先は V であって、 埋め込み X そのものではありません。 q·k は「どれだけ見るか」だけを決め、「何を持ってくるか」は V が担います。 この2つを分けられることが、Q・K・V を3つに分ける理由です。

式で書くと

文のトークン数を n = 4、埋め込みの次元を d_model として、 入力を行列 X ∈ ℝ^(n×d_model) に並べます。行が1つの語です。 このページでは X を単位行列にしています。 第 t 軸は「その語が t 番目の語かどうか」だけを表し、 それ以外の意味を持ちません。

I like play foot x_I = [ 1, 0, 0, 0 ] x_like = [ 0, 1, 0, 0 ] x_playing = [ 0, 0, 1, 0 ] x_football = [ 0, 0, 0, 1 ]

こうしておくと x_t W は「W の第 t 行を取り出す」ことと同じになります。 つまり W^Q の playing 行が、そのまま playing の query です。 実際のモデルの埋め込み表引きも、内部的にはこれと同じ演算です。

まず、同じ X を3通りに線形射影します。

Q = X W^Q W^Q ∈ ℝ^(d_model×d_k) K = X W^K W^K ∈ ℝ^(d_model×d_k) V = X W^V W^V ∈ ℝ^(d_model×d_v)

次に、語 i の query と 語 j の key の内積でスコアを作ります。 √d_k で割るのは、次元が大きいほど内積の分散が d_k に比例して 大きくなり、softmax が飽和して勾配がほぼ消えてしまうためです。

s_ij = (q_i · k_j) ⁄ √d_k ← 語 i から見た語 j の関連度 a_i: = softmax(s_i:) ← 行ごとに正規化。Σ_j a_ij = 1

最後に、その配分で value を混ぜます。これが語 i の文脈ベクトルです。

z_i = Σ_j a_ij v_j Z = A V = softmax(Q Kᵀ ⁄ √d_k) V

softmax(Q Kᵀ ⁄ √d_k) は 4×4 の行列で、 その第 i 行が語 i の重み配分です。行と列で役割が違うことに注意してください。

行 i = 「語 i が文脈を作るために、どこをどれだけ見たか」（和が 1）

列 j = 「語 j が、他のどの語からどれだけ見られたか」（和は 1 にならない）

I, like, playing, football の4語それぞれについて 1本ずつ z_i ができます。同じ語でも、周りの語が変われば z は変わります。 これが「文脈が反映されたベクトル」という言い方の中身です。

注目する語を選ぶ

計算の設定

attention 行列 A = softmax(Q Kᵀ ⁄ √d_k)

行見出しをクリックすると、その語の計算が下に展開されます。

STEP 1

この語の query を作る

埋め込みに W^Q を掛けて、この語が何を探しているかを取り出します。 x は one-hot なので、この掛け算は W^Q から1行を引くのと同じです。

STEP 2 & 3

4つの key すべてと内積を取り、softmax で配分にする

自分自身の key とも内積を取ります（self-attention なので自分も参照先の候補です）。 最終列の和が 1 になっていることを確かめてください。

相手 j k_j q·k（生） q·k ÷ √d_k a_ij（softmax後）

STEP 4

その配分で value を混ぜる

棒の長さが a_ij、右の式が実際に足し込まれた a_ij · v_j です。 混ざっているのは v であり、埋め込み x ではありません。

RESULT

入力ベクトルと文脈ベクトルを比べる

x は「その語かどうか」だけの軸、z は value 空間の軸で、 住んでいる空間が違います。実際のモデルはこのあと W^O で 元の d_model 次元へ戻し、残差接続で x に足し込みます。 下の「この計算の前後に起きること」を参照してください。

使用したパラメータと途中結果

すべての行列を隠さずに載せます。上の数値はすべてここから計算されています。

X が単位行列なので、Q, K, V は それぞれ W^Q, W^K, W^V と同じ表になります。 行列の掛け算が表引きに退化しているだけで、式は何も変わっていません。 一方 V の各行は one-hot ではありません。 v_j ≠ x_j であることが、 「重みが掛かる先は V であって埋め込みではない」の具体的な中身です。 なお、このページは位置符号を足していません（次節を参照）。

4つの文脈ベクトルをどう読むか

4語すべてを順にクリックすると、同じ計算が4回行われて4本の z が並びます。 既定の設定では、次のような読み方になります。

入る前の x は、どれも自分の軸だけが 1 の、周りを何も知らないベクトルでした。 出てきた z は、4本の v を配分どおりに混ぜたベクトルです。 この違いが「文脈が反映された」という言い方の中身です。

  • I は述語を探すので like を 0.730 参照します（主語 → 述語）。 z_I = 0.125·v_I + 0.730·v_like + 0.125·v_playing + 0.021·v_football。 中身の 73% が like から来ています。
  • like は目的語を探すので playing を 0.730 参照します（動詞 → 目的語）。 I like playing の結びつきがそのまま数字に出ています。
  • playing も目的語を探し、football を 0.730 参照します。 z_playing は v_football が支配的な混合になります。 同じ playing でも、後ろが tennis なら別のベクトルになります。
  • football は述語を探し、playing を 0.651 参照します（目的語 → 述語）。 自分自身も 0.242 残るので、z_football は 「playing 寄りに引かれた football」になります。

因果マスクを入れて playing をもう一度見てください。 football が見えなくなるので配分が [0.461, 0.079, 0.461, 0] に変わり、 z_playing も別のベクトルになります。 語は同じでも、参照できる文脈が変われば z は変わる — これが最も直接的な確認方法です。

4行とも文法的に自然な参照先になっていますが、これは W^Q, W^K を そうなるように手で書いたからです。本物のモデルはこの配線をデータから学習します。 また、ここでは1つの head が4つの関係すべてを担っています。 実際には head ごとに別の関係を拾わせるので、1つの head の行がきれいに文法と一致するとは限りません。

この計算の前後に起きること

self-attention は Transformer の一部です。前後に何があるかを押さえると、位置づけがはっきりします。

前: positional encoding

attention は語順を見ません。入力の行を並べ替えると出力の行も同じように 並べ替わるだけで（置換同変）、各語の z は変わりません。 playing が football の前にある、という情報は attention ではなく埋め込みに足し込まれた位置符号が運びます。

x_t = e(token_t) + p(t)

このページでは p(t) を足していません。 4語は埋め込みが互いに違うので、足さなくても区別はつきます。 足していない影響は、football playing like I と並べ替えても 各語の z がまったく同じになることです。 語順を扱うには位置符号が要る、というのはこの意味です。

後: 出力射影と残差接続

z_i はそのまま次の層へ行くわけではありません。W^O で d_model 次元に戻し、元のベクトルに足します。 つまり文脈の反映は上書きではなく更新です。 x_i が持っていた情報は失われません。

x_i ← LayerNorm(x_i + z_i W^O)

並列: multi-head attention

同じ計算を h 組の (W^Q, W^K, W^V) で並列に行い、 結果を連結して W^O に通します。 head ごとに違う関係（主語→動詞、動詞→目的語、固有名詞の照応…）を拾わせるためです。 このページは h = 1 なので、1つの head が全部を背負っています。

MultiHead(X) = [head₁ ; … ; head_h] W^O head_m = softmax(Q_m K_mᵀ ⁄ √d_k) V_m

並列: 因果マスク

GPT のような decoder は「次の語を当てる」ように訓練するため、 j > i のスコアを −∞ にして未来を見せません。 上のトグルを入れると行列の右上が消え、各行の配分が計算し直されるのが確認できます。 BERT のような encoder はマスクを掛けず、文全体を双方向に見ます。

後: feed-forward network

attention のあとには位置ごとに独立な2層 MLP が入ります。 attention が語の間で情報を混ぜる層、FFN が 混ぜた情報を1語の中で加工する層、という分担です。 この2つの繰り返しが Transformer ブロックです。

関連: cross-attention

Q と K, V を別の系列から作ると cross-attention になります。 翻訳なら Q が出力側、K, V が入力側です。 計算式は self-attention と完全に同じで、材料の出どころだけが違います。

つまずきやすい点

重みが掛かるのは埋め込みではなく value
z_i = Σ_j a_ij v_j であって Σ_j a_ij x_j ではありません。 もし W^V が単位行列なら両者は一致しますが、そうしないからこそ 「見る基準」と「渡す中身」を独立に学習できます。
行列は対称ではない
a_ij ≠ a_ji です。W^Q ≠ W^K だからで、 「A が B を見る強さ」と「B が A を見る強さ」は別物です。 もし W^Q = W^K にすると内積が対称になり、 各語が自分自身を最も強く見る自明な結果に寄りがちです。
softmax は行方向にだけ取る
和が 1 になるのは行です。列の和には意味がありません。 「配分」という言葉が指しているのは常に1つの語の側の配分です。
√d_k は温度ではなく分散の補正
q と k の各成分が独立で分散 1 なら、内積の分散は d_k になります。 √d_k で割ると分散が 1 に戻ります。上のトグルを外すと、 割らない場合に softmax が鋭くなる（1つの語に偏る）ことが確認できます。
「文脈を反映」は置き換えではない
残差接続 x + zW^O があるので、元の語の情報は残ります。 層を重ねるたびに、少しずつ文脈が足されていく形です。
