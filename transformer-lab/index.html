先に断っておくこと。 ここで使う W^Q, W^K, W^V は 学習で得た値ではありません。「主語は述語を探す」「動詞は目的語を探す」 という関係が現れるように手で書いた値です。埋め込みの軸に読める意味を与えているのも 説明のためで、本物はそうではありません（03）。 次元も d_model = 4, d_k = 2 と極端に小さく、head は1つだけ、 位置符号も足していません。示したいのは値そのものではなく、 値がどう流れて文脈ベクトルになるかです。

01何を作りたいのか — x から z へ

self-attention は、文の中の各語（例: playing）が同じ文の他のすべての語を見に行き、 自分にとって必要な情報だけを取り込んで、自分のベクトル（x_playing → z_playing）を 作り直す仕組みです。入口と出口だけを書くと、やりたいことは1行で済みます。

x_playing ← "playing" という語だけの情報を持つベクトル（周りを何も知らない） ↓ self-attention z_playing ← 同じ "playing" だが、周りの語から必要な分を取り込んだベクトル

重要なのは、z が語ではなく「その文脈に置かれたその語」を表すことです。 同じ playing でも、後ろが football か the piano かで z は別のベクトルになります。この「作り直し」の中身が、以降の 02〜06 です。

例文は I like playing football の4語に固定します。 実際のトークナイザは句点も1トークンに数え、語によってはサブワードに割りますが、 ここでは計算そのものに集中するため4語に簡略化しています。

02なぜ Q, K, V の3つに分けるのか

3つとも同じ入力から作られます。同じものから3つ作るのは無駄に見えますが、 役割が違います。図書館で本を探す場面に当てはめると、順番に納得できます。

  1. QQuery

    何を探しているか

    自分が文脈から何を補いたいかを表すベクトル。検索窓に打ち込む言葉にあたります。 語ごとに1本あり、q_i = x_i W^Q で作ります。

  2. KKey

    自分は何として差し出せるか

    他の語から見つけてもらうための見出し。本の背表紙にあたります。 q との内積で噛み合いを測るので、k は q と 同じ次元 d_k に住まなければなりません。k_j = x_j W^K。

  3. VValue

    実際に渡す中身

    見つけてもらったときに相手へ渡す情報。本の中身にあたります。 背表紙と中身が別物でよいのと同じで、k と v は違うベクトルです。 v_j = x_j W^V。

ここが最も間違えやすい点です。 重みが掛かる先は V であって、埋め込み X そのものではありません。 q·k は「どれだけ見るか」だけを決め、「何を持ってくるか」は V が担います。 この2つを独立に学習できることが、3つに分ける唯一にして最大の理由です。

式にすると、これだけです。以降の節は、この1行の中身を左から順に開いていく作業になります。

Attention(Q, K, V) = softmax( Q Kᵀ ⁄ √d_k ) V

03入力 X を用意する

文のトークン数を n = 4、埋め込みの次元を d_model として、 入力を行列 X ∈ ℝ^(n×d_model) に並べます。行が1つの語、 列がその語の「特徴」です。ここでは d_model = 4 とし、 4つの軸に 主体 / 動作 / もの / スポーツ を立てます。

主体 動作 もの スポーツ x_I = [ 1.0, 0.0, 0.1, 0.0 ] ← 主体そのもの x_like = [ 0.3, 1.0, 0.1, 0.0 ] ← 動作。主体の側にも少し寄る x_playing = [ 0.0, 0.6, 0.2, 0.9 ] ← 動作でもあり、スポーツでもある動名詞 x_football = [ 0.1, 0.1, 1.0, 0.3 ] ← もの。スポーツの色を帯びる

1語が1つの特徴だけを持つのではなく、複数の特徴を配合として持つことが要点です。 playing が 動作 0.6 と スポーツ 0.9 を併せ持っているのは、 これが動名詞だからです。この配合の違いが、以降の計算をそのまま動かします。

本物の埋め込みの軸に、こういう意味はありません。 実際のモデルの d_model は数百〜数千あり、意味は特定の1軸ではなく 多数の軸に分散して載っています。1軸を取り出しても、人間が読める概念には対応しません。 ここで軸に名前を付けているのは、次の 04 で W が「入力のどの特徴を、どれだけ拾うか」を決める行列であることを 数字で見せるためです。拾われる側に名前がないと、その働きが追えません。

意味を与えているのは、この埋め込みの軸だけです。 このあと出てくる query/key の平面と value 空間の軸には 意味を置かず、軸1, 軸2 と番号でだけ呼びます。理由は 05 で述べます。

04W は特徴を取り出す行列である

q_i = x_i W^Q という式で W^Q が何をしているかを、先に押さえます。 やっていることは1つです。x_i の成分を混ぜて、別の空間のベクトルを作る。 どう混ぜるかを決めているのが W^Q の各行です。

q_i = x_i W^Q = 0.0·(主体 の行) + 0.6·(動作 の行) + 0.2·(もの の行) + 0.9·(スポーツ の行) ↑ x_playing の成分

W^Q は d_model 個の行を持ち、第 t 行は 「その特徴を持つ語を、行き先の空間のどちらへどれだけ押すか」を表します。 入力の成分がその行をどれだけ使うかを決めるので、 ある特徴を持たない語は、その行を1ミリも使いません。 playing は 主体 が 0.0 なので、主体の行は結果に一切効きません。

W^K, W^V も同じ形の行列です。同じ x_i に3通りの混ぜ方を当てて、 3つの別々の特徴を取り出しているのが 02 で見た Q・K・V の分業です。

画像のフィルタとの対応

1つの入力に複数のフィルタを当てて別々の特徴マップを得る、という画像の直感がそのまま当たります。 multi-head はさらに近く、h 組の (W^Q, W^K, W^V) を並列に当てるのは、 畳み込み層が出力チャンネルを何十本も持つのと同じ構図です。

ただし対応するのは 3×3 のフィルタではなく 1×1 の畳み込みです。 「周囲との差分を取る」フィルタは複数のピクセルをまたいで混ぜますが、 W^Q が混ぜるのは1つの語のベクトルの中の成分どうしだけで、 隣の語には一切触れません。

位置をまたいで混ぜる 各位置の中で混ぜる
CNN 3×3 畳み込み（重みは固定・局所） 1×1 畳み込み
Transformer attention（重みは入力依存・全域） W^Q, W^K, W^V, FFN

つまり Transformer で「語をまたいで混ぜる」役は W ではなく attention 自身です。しかも畳み込みと違い、混ぜる相手と配合比が 入力ごとに変わります。それが 06 以降で計算する a_ij です。

もう1つ違いがあります。畳み込み層の出力チャンネルは、どれも次の層へ同じように渡されます。 Q, K, V はそうではありません。 Q と K は内積で突き合わされるので同じ空間に住む必要があり、 V は運ばれる中身なので次元すら違ってよい。 「3種類のフィルタ」というより「役割が3つに分かれている」ほうが実態に合っています。

053つの射影で Q, K, V を作る

02 で決めた3つの役割を、同じ X への3通りの線形射影として作ります。 違うのは掛ける行列だけです。

Q = X W^Q W^Q ∈ ℝ^(d_model×d_k) d_k = 2 K = X W^K W^K ∈ ℝ^(d_model×d_k) d_k = 2 ← q と内積を取るので同じ次元 V = X W^V W^V ∈ ℝ^(d_model×d_v) d_v = 4 ← 次元は q, k と違ってよい

04 で見たとおり、各 W の行は「その特徴を、行き先の空間のどちらへ押すか」です。 以下では W（行が特徴）と、その結果である Q/K/V（行が語）を 必ず対にして出します。行の意味が違うので、片方だけでは読み違えます。 まず入力の X です。

この平面の「軸」には意味がない

d_k = 2 は query と key が住む平面です。 03 の埋め込みの軸には 主体 や スポーツ という意味がありましたが、 この平面の軸には対応する意味がありません。理由ははっきりしています。 attention がこの平面から取り出す情報は内積 q·k だけで、 すべての q と k を同じ角度だけ回転させても内積は1つも変わらないからです。 当然、出てくる z も完全に同じになります。

つまり座標軸の取り方は任意で、意味を持つのはベクトルどうしの相対的な向きと長さだけです。 そのためこのページは軸に名前を付けず、表の列見出しでは 軸1, 軸2 と番号でだけ呼びます。 以下では、この平面に矢印を描いて数値と並べます。表の数値は、そのまま矢印の座標です。

W^K — 特徴が、語を平面のどこへ置くかを決める

key は「自分は何として差し出せるか」という見出しでした（02）。 W^K の4つの行は、4つの意味特徴が、この平面のどちらへ語を押すかを表します。 下の図の灰色の細い矢印がその4本です。語の key は、 その語が持つ特徴ぶんだけ灰色の矢印を足し合わせたもの（色の矢印）になります。

特徴の配合が違えば、足し合わせた先も違う。だから4語は平面の別々の場所に落ちます。 向きが互いに違うことが、そのまま「4語が見分けられる」ということです。 逆に2本の key がほとんど同じ向きになると、その2語はどの query から見ても ほぼ同じ内積を返すので、区別できなくなります。 「背表紙がそっくりな2冊は探し分けられない」というだけのことで、 key の配置に効いてくるのはこの一点です。

4本の向きは 20°, 75°, 170°, 285° で、 間隔は揃っていません。長さも 0.95〜1.25 とばらばらです。 内積は向きの近さと長さの積なので、 長い key はどの query からも少し強めに見られます。

W^Q — 特徴が、その語の探し先を決める

query は「何を探しているか」でした。W^Q の4つの行は、 その特徴を持つ語は、平面のどの向きの key を探しに行くかを表します。 下の図の破線が、足し合わせて出来た各語の query です（薄い実線は先ほどの key）。

主体 の行は k_like の方（主体らしい語は動作を探す）、 動作 と もの の行は k_playing の方、 スポーツ の行は k_football の方を向けてあります。

いちばん見てほしいのは playing です。 この語は 動作 0.6 と スポーツ 0.9 を併せ持つので、 動作 の行の左向きと スポーツ の行の右下向きが足し合わさり、 合成された q_playing は真下、つまり k_football の方を向きます。 どの行も単独では k_football を狙っていないのに、 特徴の配合が探し先を決めているのが見えます。

各行の向きは、狙う key と完全には一致させていません。 内積は向きが近いほど大きくなるので、 完全に一致していなくても、他の3つより内積が大きければ、 softmax のあとの配分もその語が最大になります。

つまり query の向きが「どの語の内積が最も大きくなるか」を、 長さが「その差をどれだけ広げるか」を決めます。 query を長くすると4つの内積がまとめて比例して大きくなり、 softmax に入る値の差も広がるので、配分が1語に集中します。 短くすれば差が縮まり、配分は平らに近づきます。 ここでは長さを 2.4 前後にしてあり、これが 06 で見る配分の鋭さになります。

これらの値は学習で得たものではなく、上のような関係が現れるように手で書いたものです。 本物のモデルは、この向き合わせをデータから学習します。

W^V — 中身は、見出しと無関係でよい

value に課される条件はさらに緩く、key と揃っている必要すらありません。 住む空間も別で、ここでは d_v = 4 です。 こちらの軸にも意味はないので、同じく 軸1〜軸4 と番号で呼びます。

下の V の表を、03 の X の表と見比べてください。 同じ語なのに、まったく別のベクトルになっています。 この v_j ≠ x_j が、02 の 「重みが掛かる先は V であって埋め込みではない」の具体的な中身です。

061語を選んで最後まで追う

ここからが本題です。1語だけを選び、その語の z ができるまでを STEP 1 から RESULT まで、途中の数字を丸めずに順に見ます。 既定は playing です。まずはこのまま下へ読み進めてください。

注目する語

STEP 1

この語の query を1本作る

埋め込みに W^Q を掛けて、この語が何を探しているかを取り出します。 04 で見たとおり、これはこの語が持つ特徴ぶんだけ W^Q の行を足し合わせる 操作です。成分が 0 の特徴は、その行を1ミリも使いません。

STEP 2

4つの key すべてと内積を取る

STEP 1 で作った q と、4語ぶんの k の内積を取ります。 自分自身の key とも取ります（self-attention なので自分も参照先の候補です）。 内積が大きいほど「噛み合っている」ことになります。

05 の平面に、いま選んでいる語の q だけを重ねたのが下の図です。 q に向きが近い k ほど内積が大きくなります。 表の「q · k_j（生）」の列は、この図を数値にしたものです。

相手 j k_j q · k_j（生） s_ij = q·k ⁄ √d_k

√d_k で割るのは温度調整ではなく分散の補正です。 q と k の各成分が独立で分散 1 なら内積の分散は d_k になり、 次元が大きいほど次の softmax が飽和して勾配がほぼ消えます。 √d_k で割ると分散が 1 に戻ります。 上のチェックを外すと、割らない場合に配分が鋭くなる（1語に偏る）ことが下で確認できます。

STEP 3

softmax で「配分」に変える

STEP 2 のスコアはまだ大小がばらばらの実数です。これを 足して 1 になる比率に直すのが softmax です。 最大値を引いてから指数を取っているのは、指数のオーバーフローを避けるためで、結果は変わりません。

相手 j s_ij exp(s_ij − max) a_ij = exp ⁄ Σexp

最終列の合計が 1.000 になっていることを確かめてください。 この a_i: が「語 i が文脈を作るときに、どこをどれだけ見るか」の配分です。

STEP 4

その配分で value を混ぜる

STEP 3 で配分 a_i: が決まりました。あとはその配分で v を混ぜるだけです。 下の式は、記号 → 配分 → v の中身 → 結果の順に、1段ずつ具体化したものです。 2段目の係数がそのまま混合比で、3段目で 混ざっているのが v であって埋め込み x ではないことが見えます。

2段目の z_i = Σ_j a_ij v_j という書き方が、self-attention の出力の定義そのものです。 たとえば 0.867·v_football という項は「この語の新しいベクトルの 87% が football の value から来ている」と読みます。

RESULT

入る前と出た後を比べる

x は「その語かどうか」だけの軸、z は value 空間の軸で、 住んでいる空間が違います。実際のモデルはこのあと W^O で 元の d_model 次元へ戻し、残差接続で x に足し込みます（09）。

074語ぶん並べると attention 行列になる

06 でやったのは 1行ぶんの計算です。同じことを4語すべてについて行い、 配分 a_i: を縦に積むと 4×4 の行列になります。これが softmax(Q Kᵀ ⁄ √d_k) の正体で、新しい計算は何も増えていません。

a_i: = softmax(s_i:) ← 06 でやったこと（1行ぶん） A = softmax(Q Kᵀ ⁄ √d_k) ← それを4語ぶん積んだもの Z = A V ← 文脈ベクトルも4本まとめて出る

行の見出しをクリックすると、その語で 06 を計算し直します。

行 i = 「語 i が文脈を作るために、どこをどれだけ見たか」（和が 1）

列 j = 「語 j が、他のどの語からどれだけ見られたか」（和は 1 にならない）

行と列で役割が違うことに注意してください。行列は対称ではありません。 W^Q ≠ W^K なので、「A が B を見る強さ」と「B が A を見る強さ」は別物です。

4行をそれぞれどう読むか

STEP 4 の階段の2段目（z = 0.067·v_I + …）を、4語ぶん並べたものです。 係数を横に読めば、その語の新しいベクトルがどこから何割来ているかが分かります。

    ここで因果マスクを入れてみてください。 j > i のスコアが −∞ になって行列の右上が消え、各行の配分が計算し直されます。 たとえば playing は football が見えなくなるので、 配分も z_playing も別のものになります。 語は同じでも、参照できる文脈が変われば z は変わる — 01 で述べたことの、最も直接的な確認方法です。

    4行とも文法的に自然な参照先になっていますが、これは W^Q, W^K を そうなるように手で書いたからです。本物のモデルはこの配線をデータから学習します。 また、ここでは1つの head が4つの関係すべてを担っています。 実際には head ごとに別の関係を拾わせるので、1つの head の行がきれいに文法と一致するとは限りません。

    08つまずきやすい点

    ここまでで一通り追えました。誤解しやすいところを、上の節に対応づけて並べます。

    重みが掛かるのは埋め込みではなく value（→ 02, 05）
    z_i = Σ_j a_ij v_j であって Σ_j a_ij x_j ではありません。 もし W^V が単位行列なら両者は一致しますが、そうしないからこそ 「見る基準」と「渡す中身」を独立に学習できます。
    q·k はまだ文脈を反映していない（→ STEP 2, 3）
    s_ij = q_i · k_j は語 i と語 j の2つだけから決まる数値で、 文中に他の語が何個あっても変わりません。q_i, k_i, v_i も その語だけから作られます。文脈が入るのは softmax の分母で全語を足し合わせる瞬間で、 文脈を反映したベクトルは z_i のほうです。 因果マスクを入れて playing の行を見てください。 q·k の列がまったく変わらないまま、配分だけが変わります。
    行列は対称ではない（→ 07）
    a_ij ≠ a_ji です。W^Q ≠ W^K だからで、 もし W^Q = W^K にすると内積が対称になり、 各語が自分自身を最も強く見る自明な結果に寄りがちです。
    softmax は行方向にだけ取る（→ 03, 07）
    和が 1 になるのは行です。列の和には意味がありません。 「配分」という言葉が指しているのは、常に1つの語の側の配分です。
    √d_k は温度ではなく分散の補正（→ STEP 2）
    次元が大きいほど内積の分散が d_k に比例して大きくなるのを打ち消すためのものです。 「softmax を鈍らせたいから割る」のではありません。
    「文脈を反映」は置き換えではない（→ 09）
    残差接続 x + zW^O があるので、元の語の情報は残ります。 層を重ねるたびに、少しずつ文脈が足されていく形です。

    09この計算の前後にあるもの

    06 で見たのは Transformer の一部分です。最後に、前後に何があるかを 処理の順番どおりに並べて、位置づけをはっきりさせます。

    1. 前

      positional encoding

      attention は語順を見ません。入力の行を並べ替えると出力の行も同じように 並べ替わるだけで（置換同変）、各語の z は変わりません。 playing が football の前にある、という情報は attention ではなく埋め込みに足し込まれた位置符号が運びます。

      x_t = e(token_t) + p(t)

      このページでは p(t) を足していません。 4語は埋め込みが互いに違うので、足さなくても語の区別はつきます。 足していない影響は、football playing like I と並べ替えても 各語の z がまったく同じになることです。

    2. ここ

      self-attention（このページ）

      Q, K, V を作り、q·k で配分を決め、 その配分で v を混ぜて z を得る。01〜07 で追ったのはここです。

    3. 同時に

      multi-head attention

      まったく同じ計算を h 組の (W^Q, W^K, W^V) で並列に行い、 結果を連結して W^O に通します。 head ごとに違う関係（主語→動詞、動詞→目的語、固有名詞の照応…）を拾わせるためです。 このページは h = 1 なので、1つの head が全部を背負っています。

      MultiHead(X) = [head₁ ; … ; head_h] W^O head_m = softmax(Q_m K_mᵀ ⁄ √d_k) V_m

    4. 同時に

      因果マスク（decoder かどうか）

      GPT のような decoder は「次の語を当てる」ように訓練するため、 j > i のスコアを −∞ にして未来を見せません。 07 のトグルで確かめたのがこれです。 BERT のような encoder はマスクを掛けず、文全体を双方向に見ます。

    5. 直後

      出力射影 W^O と残差接続

      z_i はそのまま次の層へ行くわけではありません。W^O で d_model 次元に戻し、元のベクトルに足します。 つまり文脈の反映は上書きではなく更新で、x_i が持っていた情報は失われません。

      x_i ← LayerNorm(x_i + z_i W^O)

    6. そのあと

      feed-forward network

      attention のあとには位置ごとに独立な2層 MLP が入ります。 attention が語の間で情報を混ぜる層、FFN が 混ぜた情報を1語の中で加工する層、という分担です。 この2つの繰り返しが Transformer ブロックです。

    7. 別の使い方

      cross-attention

      Q と K, V を別の系列から作ると cross-attention になります。 翻訳なら Q が出力側、K, V が入力側です。 計算式は 06 で追ったものと完全に同じで、材料の出どころだけが違います。
